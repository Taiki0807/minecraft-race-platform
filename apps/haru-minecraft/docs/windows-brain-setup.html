haru-minecraft / Windows セットアップ

ハル・ブレイン セットアップ手順

AI VTuber「ハル」が自動でマイクラをプレイする仕組みのうち、「頭」(判断ループ・記憶・Creator Studio連携)を このWindows機(GPU搭載・ローカルLLM/TTSと同じ機)に導入するための作業指示書。

このマシンに新しく用意するもの
apps/haru-minecraft(ハルの「頭」) — この手順の対象
既にこのマシンで動いていて、変更不要なもの
Creator Studio / ローカルLLM(/chat) / Irodori TTS
別担当者が同じマシン上に用意する予定
FastAPIによるGPU推論サービス(別紙の依頼仕様書を参照)
1前提確認 2コード配置 3依存インストール 4.env 設定 5起動確認 6常時稼働化 7GPUサービス連携 ✓最終チェック
STEP 1

前提確認

始める前に、このマシンから到達できるものを確認する。

□Node.js 22以上が入っている(node -v)
□Proxmox側の haru-body(ポート3300)にこのマシンから到達できる(担当のネットワーク経路/Tailscale等)
□同一マシンの Creator Studio(通常 http://127.0.0.1:3100)に到達できる
STEP 2

コードをこのマシンに配置する

minecraft-race-platform リポジトリの apps/haru-minecraft ディレクトリを このマシン上に用意する(cloneでもコピーでも、普段使っている方法でよい)。 

# 例: 既にリポジトリをこのマシンに持っている場合
cd minecraft-race-platform
git pull
cd apps\haru-minecraft
STEP 3

依存関係をインストール

cd apps\haru-minecraft
npm install
□エラー無く完了する(警告は無視してよい)
STEP 4

.env を設定する

.env.example を .env としてコピーし、以下の値を記入する。 Secretはこのファイルにのみ書き、他に貼らないこと(.env はgit管理外)。 

copy .env.example .env
変数名説明値の出どころ
STUDIO_BASE_URLCreator Studioの受信先同一機なら http://127.0.0.1:3100(既定のままでよい)
STUDIO_TOKENCreator Studio認証用Creator Studio側 .env.local の MINECRAFT_BRIDGE_TOKEN と同じ値
BRAIN_PORTこのプロセス自身の制御ポート既定の 3200 でよい
BRAIN_TOKEN/control /status の保護任意のランダム値(本番では設定推奨。空だと認証無し)
LLM_PROVIDERhome-llm または ollama最初は home-llm。STEP 7でFastAPI完成後に ollama へ切替
LOCAL_LLM_URL / LOCAL_LLM_TOKEN既存のローカルLLM(/chat)既存の値をそのまま流用
BODY_BASE_URLharu-body(Proxmox側)の接続先http://<Proxmox側アドレス>:3300
BODY_TOKENharu-body認証用Proxmox側 apps/haru-body/.env の BODY_TOKEN と同じ値
HARU_PERSONA_PROMPTハルの人格プロンプト空でよい(最低限のフォールバック文が自動で入る)
□STUDIO_TOKEN と BODY_TOKEN は、相手側の値と文字単位で一致しているか必ず見比べる
STEP 5

起動して配線を確認する

npm run dev

起動ログに次が出るか確認する:

[haru-minecraft] haru-body に接続した (tools: 12)
[haru-minecraft] control server listening on :3200 (...)

別のコマンドプロンプトから:

curl http://127.0.0.1:3200/status
□{"online":true,"state":"idle",...} が返る
「haru-body に接続した」が出ない場合

BODY_BASE_URL の到達性、BODY_TOKEN の一致、Proxmox側で haru-body 自体が起動しているかを確認する。

STEP 6

常時稼働化(タスクスケジューラ登録)

確認が済んだら、起動時自動実行・クラッシュ時再起動するよう登録する。

npm run build
powershell -ExecutionPolicy Bypass -File scripts\register-task.ps1
□Start-ScheduledTask -TaskName haru-minecraft で起動し、/status が応答する
STEP 7

GPU推論サービス(FastAPI)が出来たら

未着手・担当者待ち

別紙「GPU推論サービス 依頼仕様書」に基づいてFastAPIサービスが用意できたら、 .env を書き換えてタスクを再起動する。 

LLM_PROVIDER=ollama
OLLAMA_BASE_URL=<FastAPIサービスのURL>
OLLAMA_MODEL=<モデル名>
Restart-ScheduledTask -TaskName haru-minecraft
□logs/*.jsonl の decision ログに tool_calls が正しい形式で入っているか確認する
✓

最終チェックリスト

Node.js・ネットワーク到達性を確認した(STEP 1)
npm install が完了した(STEP 3)
.env の各トークンが相手側と一致している(STEP 4)
npm run dev で haru-body への接続ログが出た(STEP 5)
/status が応答する(STEP 5)
タスクスケジューラに登録し、再起動後も動くことを確認した(STEP 6)
(FastAPI完成後)LLM_PROVIDER=ollama に切り替えて tool_calls が返ることを確認した(STEP 7)
この手順はコード・設定ファイルの作成時点での想定に基づく(実機未検証)。詰まった箇所は apps/haru-minecraft/docs/verification-runbook.md の段階的確認手順も参照。
